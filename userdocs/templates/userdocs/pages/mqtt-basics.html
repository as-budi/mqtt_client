MQTT is a small publish/subscribe protocol used by many IoT devices. Devices and apps never talk to each other directly: everyone connects to a broker, which forwards each message to whoever subscribed to its topic.

Topics

A topic is a text path with levels separated by /, for example lab/room1/temperature. Topics are case sensitive and need no registration: publishing to a new topic simply creates it.

Wildcards

FilterMatchesDoes not match
lab/+/temperaturelab/room1/temperature, lab/room2/temperaturelab/room1/a/temperature
lab/#lab, lab/room1, lab/room1/temperaturelabs/room1

Wildcards are only for subscribing. + stands for exactly one level, # for any number of levels and must be last. You cannot publish to a topic that contains them.

Quality of service (QoS)

QoSMeaningTypical use
0at most once: sent once, may be lostfrequent sensor values
1at least once: repeated until confirmed, may arrive twicecommands, alarms
2exactly once: a longer handshakerarely needed; not every broker supports it

A message is delivered with the lower of the publisher's and the subscriber's QoS.

Retained messages

With Retain, the broker keeps the last message of a topic and gives it to every new subscriber at once, e.g. the current state of a lamp. Retained messages are marked in the message list. To remove one, publish an empty retained message to the same topic (Clear retained in the Publish card).

Client ID, keep alive and clean start

  • Client ID: each connection to a broker needs a unique ID; a second connection with the same ID pushes the first one out. This app adds a random ending to the prefix of your profile every time you connect, so two tabs do not collide.
  • Keep alive: when nothing is sent for this many seconds, the client sends a small ping so the broker knows it is still there.
  • Clean start: start with a new session every time. Without it, the broker may keep your subscriptions and queued QoS 1/2 messages while you are away.

Last Will

A message the broker publishes for you when your connection is lost without a proper disconnect, e.g. offline to lab/node1/status (often retained). Set it in the connection profile.

MQTT 3.1.1 and MQTT 5

Both versions work with most brokers. MQTT 5 adds properties such as message expiry, content type, response topic and user properties (see Reading messages). Choose the version in the connection profile.
