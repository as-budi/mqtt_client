On a connection made from an IoT Platform device, the Automation card has a Behave like the device part. It lets this page act like the firmware templates of IoT Platform, so you can try dashboards, rules, commands and firmware updates without an ESP32.

Simulated sensors

Simulate sensors fills the Publish card with the device's telemetry topic and a payload built from its variables on IoT Platform: {% templatetag openvariable %}random:min:max}} using each sensor's limits (0–100 when none are set), and {% templatetag openvariable %}int:0:1}} for on/off sensors. Actuators are left out. Press Start next to Publish the message above every N s to send it repeatedly; the values appear on IoT Platform and in the Charts tab here.

Answering commands

With Answer commands automatically, every command received on …/commands/<id> is answered on …/commands/<id>/response with the template below the option, by default {"success": true, "method": "{% templatetag openvariable %}method}}"}. The template may use {% templatetag openvariable %}id}} and {% templatetag openvariable %}method}}. Change it to {"success": false, "error": "…"} to test a failing device.

Like the ESP32 firmware, a command whose expires_at has already passed (by more than two seconds on your computer's clock) is neither run nor answered; the line under the template says so. IoT Platform has already marked it Expired.

Requested states

With Report desired states back as telemetry, a requested state such as {"lamp": 1} received on …/desired is sent back on the telemetry topic, as a device does after switching. On IoT Platform the actuator turns In sync.

Rule JSON

Publish to devices on a rule page of IoT Platform sends the whole rule as JSON to …/rules/<id> (retained). With Acknowledge rule JSON automatically (on by default), the page answers on …/rules/<id>/ack with the reply template, by default {"publish": {% templatetag openvariable %}publish}}, "ok": true, "size": {% templatetag openvariable %}size}}}.

Reply now sends the template for the last rule received (handy when the automatic answer is off); Reset restores the default template.

Firmware updates

With Simulate firmware updates (OTA), an ota command is accepted and followed by progress reports on …/firmware, like the ESP32 firmware: DOWNLOADING 0–100 %, DOWNLOADED, VERIFIED, UPDATING, and finally the new version with board and MAC address. Choose Fail to stop at 50 % with FAILED. Start the update from the firmware page of IoT Platform and watch its status there.

The MAC address is the one IoT Platform knows for the device, or, if it has none yet, a made-up address that stays the same for the device (starting with 02:).

Automatic messages in the list

Automatic answers and reports appear in the message list as published messages (↑), but not in the Publish history.
